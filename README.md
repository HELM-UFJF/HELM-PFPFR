# HELM-PFPFR: Power flow with primary frequency regulation in the holomorphic load flow

MATLAB code and data for the paper

> G. R. S. Lima, E. J. Oliveira, L. W. Oliveira, "Holomorphic embedding power flow with primary frequency regulation and generator active and reactive power limits," submitted to *International Journal of Electrical Power & Energy Systems*, 2026.

The code solves the Power Flow with Primary Frequency Regulation (PF-PFR) by the Holomorphic Embedding Load Flow Method (HELM) and by the Newton–Raphson (NR) method, with the same model and the same outer loop:

- the frequency deviation is one more power series, coupled to the active-power equations through the droop of each unit and the frequency sensitivity of the load, so the slack bus no longer absorbs the whole imbalance;
- the recursion matrix is constant for all orders and is factorized once per pass, with several units allowed at the same bus;
- one outer loop saturates the violating units in blocks, releases those that return within their limits, and switches buses between voltage control and reactive limit;
- all power series are evaluated in a single step per order by an incremental form of Wynn's epsilon algorithm;
- the operating points come from an AC optimal power flow with a system reserve requirement, in which each unit holds at most the reserve that its droop delivers before the first stage of under-frequency load shedding.

## Requirements

- MATLAB R2018a or later (tested with R2018a and R2026b). The code also runs in GNU Octave 8.
- No toolbox is required.
- [MATPOWER](https://matpower.org) (tested with version 8.1) is required only by `Main_Contingencias.m`, which compares the PF-PFR with the classical power flow and validates the results with `runpf`, and by the scripts in `geracao/`, which regenerate the operating points.

## Reproducing the results

Run the main scripts from the root folder of the repository; each script adds `funcoes` and `dados` to the path and writes its data files to `resultados`.

| Script | Results in the paper | MATPOWER |
| --- | --- | --- |
| `Main_Tutorial3Barras.m` | Three-bus tutorial: Table 3 and Fig. 4 | No |
| `Main_Wang39.m` | Reproduction of the IEEE 39-bus case of Wang et al.: Section 6.1 | No |
| `Main_PontosOperacao.m` | Operating points and reserve margins: Table 4 and Fig. 6 | No |
| `Main_Contingencias.m` | Classical power flow versus PF-PFR and loss of generation: Tables 5 and 6, Figs. 7 and 8 | Yes |
| `Main_Deficit.m` | Generation-deficit sweep: Fig. 9 | No |
| `Main_Benchmark.m` | Computational effort: Table 7 and Fig. 10 | No |
| `Main_Todos.m` | Runs all scripts above except `Main_Benchmark.m` and checks every output file against `referencia/` | Optional |

`Main_Todos.m` takes about one minute and reports, for each data file, the largest difference from the values of the paper. Without MATPOWER on the path, it skips `Main_Contingencias.m` and checks the remaining files.

Computing times depend on the MATLAB version and on the computer; `Main_Benchmark.m` reports the median of 20 runs.

## Main function

```matlab
[V, lam, Pg, info] = FPRP_Resolver(D, metodo, tol, nmax)
```

- `D`: system data built by `FPRP_Dados_MP` from a MATPOWER case;
- `metodo`: `'HELM'` or `'NR'`;
- `V`: complex bus voltages (p.u.); `lam`: frequency deviation, with f = f0 (1 − lam); `Pg`: active power of the units (p.u.);
- `info`: convergence flag, passes of the outer loop, number of HELM orders or NR iterations, saturated units, and final reactive state of the buses.

## Test systems and operating points

| File | Description | Source |
| --- | --- | --- |
| `case3_tutorial_c_perdas.m` | Three-bus tutorial system | Lima (2024), master's thesis, UFJF |
| `case39.m` | IEEE 39-bus system | MATPOWER |
| `pglib_opf_case118_ieee.m` | IEEE 118-bus system with generator costs and limits | PGLib-OPF v23.07 |
| `case_ACTIVSg2000.m` | Synthetic 2000-bus Texas system | MATPOWER / Texas A&M University |
| `case_ACTIVSg2000_h5368.m`, `case_ACTIVSg2000_h8504.m` | Hours 5368 (annual peak) and 8504 (light load) of the 2016 time series | [HELM-AIC](https://github.com/HELM-UFJF/HELM-AIC) ([doi:10.5281/zenodo.24318005](https://doi.org/10.5281/zenodo.24318005)) |
| `case118_fprp.m`, `case_ACTIVSg2000_fprp_h5368.m`, `case_ACTIVSg2000_fprp_h8504.m` | Operating points of the study: AC OPF with a system reserve requirement | Generated by `geracao/Gera_Base_FPRP.m` |

To regenerate the operating points, add MATPOWER to the path, change to the folder `geracao`, and run `Gera_Base_FPRP.m`; the files are written to `dados`. The construction of the operating points is described in Section 5 of the paper.
